## 第二批发现与修复

复现命令：`node --test scripts/test-policy-revocation.mjs`。

1. **preset 清单为空时跳过整轮撤权**：导致模式、owner、白名单或黑名单变化不能及时
   退役旧映射。现在仅推迟依赖清单的 preset 比对，本地已知的权限变化立即处理；
   清单故障本身不会使权限未变的会话退役。
2. **无 DSH 映射时提前返回**：已有二代状态的会话仍可能持有 token 和定时器。
   现在同样清理，并按状态对象记住已撤权结果，避免每次轮询都反复换 token、写盘。
3. **旧消息队列残留**：撤权后重新加入白名单，旧投递队列和断线积压可能继续执行。
   现在撤权时拒绝尚未投递的请求、删除离线积压。已提交给 DSH 的工作仍是尽力取消，
   已发生的工具副作用无法回滚。

同时验证：跨会话 token 无法读取或发送至另一白名单会话；旧 token 在移除再加入后
仍被拒绝；排队中的 AI 出站在模式变化后被取消；旧 token 保留在脱敏集合中。

## 核心消息链路拆分

`src/core/` 新增六个模块，各自有直接导入的行为测试，并已接入 `bridge.js`：

- `inbound-parser.js`：消息段、引用、成员名与媒体元数据解析；解析结果确认仍有效后才写会话缓存。
- `conversation-queue.js`：从接收时就逐会话排队；同会话 FIFO，跨会话并行，取消后旧完成不驱动新队列。
- `offline-backlog.js`：逐会话补投、容量上限、退避重试、撤权/重置取消；普通重复输入保留，显式重试可去重。
- `session-lifecycle.js`：单飞创建、安全 preset 校验、旧映射重建、创建与模型检查后的代际校验；特定功能的 token/定时器清理由退役钩子负责。
- `reply-sender.js`：文字、分条、语音和表情共用发送顺序；临发前检查权限，保留部分成功列表供调用方记账。
- `reply-formatting.js`：分条格式与 URL/字符完整性；语音回归不再截取源码 `eval`，媒体元数据测试直接导入解析模块。

本批复现并修复：慢引用查询使后来文本插队；未建立映射的离线输入未随撤权丢弃；
正在创建的会话在撤权再恢复后复活；旧模型检查结果误清新映射。补投也不再由一个慢
会话阻塞全部会话，重复触发补投不会缩短失败退避。

`npm run test:core` 包含六模块直接测试与投递顺序、混合发送、权限撤销的接线回归。
本批最终验证：核心专项 **62/62 通过**；完整离线审计 **91/91 个脚本通过，9 个脚本
仍含环境相关跳过项**。配置示例校验、主程序语法与 diff 空白检查通过。
离线积压仍在内存中，尚不提供进程重启恢复；已发出请求的副作用不能撤销。
这不替代第 6 批的持久化出站交付设计，也不代表真实 QQ/DSH 集成已验证。

## 逐会话路由主程序与控制台接线

主程序通过策略存储中的 `SessionRouter` 查询每个 key，覆盖消息接收、投递、发送、
事件回复、定时唤醒与 HTTP 授权。owner 私聊与群聊可同时采用不同工具面；策略变化
只退役对应会话，元数据变更不重建，其他会话定时器保持原样。缺失或损坏的策略不
自动启用本地执行；owner 保存同步失败会阻止继续更改策略。

修复了接线中发现的隔离问题：单会话重置的全局 epoch 波及其他创建；二代状态重置
误清 owner 映射；无关策略更新重排其他会话计时器；缓存 preset 清单阻挡安装后迁移；
加载时改 mode 但保留旧 preset 导致协议不匹配。显式模型与强度失效时不静默降级。

控制台新增迁移、逐会话编辑、变更记录、删除覆盖与回退；启用后旧模式按钮停用。
仿真提示词编辑器支持规范 preset，保存与旧 preset 相互独立。当前用户配置、状态及

## 第六批：断线交付验收

桥接在调用 DSH 前把请求 ID 和会话策略写入 `state/delivery.json`，不保存输入正文。
尚未提交的输入仍使用进程内队列。已提交但确认丢失的输入暂停该会话后续提交，直到
DSH 的 `user/message.source.rpcId` 证明接收，或操作者重置会话。重置会丢弃该会话未投递的队列。

桥接按快照游标固定历史范围，用 `session/page` 补齐旧页，然后核对回合起止和输入来源。
只恢复桥接有提交记录的完整回合。二代仿真内部文本、静默输入、审计拦截的文本，以及尝试过
QQ 发送工具的回合都没有自动文本补发。历史存在缺口时暂停该会话的自动发送，等待下一次
完整快照。显式发送工具、命令即时结果和通知继续使用各自的发送路径。

已完成回复按会话和回合去重，每段保存独立状态。桥接在调用 OneBot 前落盘发送意图，
只在收到有效的 QQ 消息 ID 后推进游标。确认丢失或在发送中重启会进入待核对状态，
后续同会话回复等待核对。已确认和已丢弃的段会清除正文。模式、绑定和权限在发送前重查。
日志上限为 10,000 个回合和 40,000 条提交记录，超限会停止新增并记录错误，不清除旧回执。

控制台令牌可调用 `GET /api/delivery` 查看待核对的输入、输出和暂停恢复的会话。
返回结果不包含正文。核对 QQ 实际记录后可用 `POST /api/delivery` 提交 `id`、
`partIndex`、`expectedRevision`、`action` 和 `reason`。已确认收到用
`acknowledge` 并提供 `verifiedMessageId`。确定未收到且希望补发用 `retry`。
无需再发用 `discard`。版本变更后须重新读取状态。没有可靠核对结果时保持待核对。

`npm run test:delivery` 通过 70 项。完整离线审计通过 97 个脚本，9 个脚本含环境相关跳过项。
真实 DSH 实测确认了提交 ID 关联以及历史分页。对一个已映射私聊的只读快照，
用 3 页补齐了 733 条连续事件，识别到 18 个完整回合。接口结构的静态来源为安装包
证据 `ev_47d42de09377d977a10c6a7e3cdb7cfb331969d122cf939888fe266edcaec826`，
实际行为由本机 RPC 另行确认。
