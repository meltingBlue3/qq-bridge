# 配置默认值与状态存储

## 配置

`src/config-defaults.js` 是唯一默认值来源。`src/config.js` 负责合并与规范化；
搜索和媒体模块也读取同一份默认值。对象递归合并，数组整体替换，显式 `0`、`false`
和空数组保留。畸形子对象不会清掉默认限制。加载配置不会改写用户的 `config.json`。

```bash
npm run build:config    # 只生成 config.example.json
npm run verify:config   # 只校验生成物；兼容 LF / CRLF
npm run test:storage    # 配置与持久化专项
npm run test:audit      # 完整离线回归，包含上述专项
```

示例不含用户 QQ、路径或凭据，语音默认关闭、空白名单默认拒绝。
旧示例里的部分数值是调优值，已统一为原加载器实际默认值：例如一代最小检测间隔
10 秒、冷场继续概率 0.25、默认确认消息“🤔 收到，正在思考…”。移除了示范中转模型的
价目表覆盖，`pricing: null` 表示使用内置价目表。现有用户配置中的显式值不变。

控制台更新白名单、安全、模型强度、人格上限及两代社交配置时，先读当前配置，再仅
改目标字段、原子写入；根级和嵌套未知字段保留。解析或写入失败不会提前修改运行配置。

## 状态文件

`src/json-store.js` 提供共用保护，领域模块保留自身的结构校验、清洗与序列化规则。

| 文件 | 接入方式 |
| --- | --- |
| `sessions.json` | `session-state.js`：校验会话映射和策略元数据，兼容缺少旧策略元数据的映射 |
| `social-v2.json` | `social-v2/state-store.js`：归一化、水位、令牌、限长保存沿用原协议；重置也经过同一存储实例 |
| `initial-prompts.json` | `initial-prompts.js`：保存失败回滚内存，加载不截断，注入时才按上限显示 |
| `slang.json` | `createSlangStore()`：数组校验、规范化、容量裁剪；损坏时尽力复制 `.corrupt-*` 原文，原文件保留 |
| `stickers.json` | `createStickerStore()`：数组校验、规范化，本地备注写失败回滚内存 |
| `mode.json`、`current-role.json` | 严格读取后更新，保留无关字段；损坏的角色状态按静默处理并告警，不自行修复原文件 |
| `feedback.json`、`slang-session.json` | 追加、清空或更新前先校验当前文档，损坏时拒绝覆盖 |

不存在的文件可在首次保存时创建。空文件、非法 JSON、顶层结构错误或读权限失败
会使长期存储实例降级为只读；后续保存不会拿空状态覆盖原件。磁盘写失败保留旧文件、
清理临时文件，并允许重试。初始提示词、黑话编辑和表情本地备注的内存修改也会回滚。
QQ 端已发生的发送或修改不属于本地文件事务，统计落盘失败不能撤销它们。

每次保存都会比较加载时与当前磁盘上的原文，发现外部修改后拒绝旧内存回写，即使
文件长度和修改时间相同也能检测。它是乐观冲突保护，检查与 rename 之间仍有竞争窗口，
不能替代单实例锁，也不支持多个进程同时修改同一状态文件。

二代暂停的内存开关立即生效；如果保存失败，接口返回错误并说明当前进程已经暂停，
恢复写入后可以重试。二代重置保存失败也会明确返回错误，不宣称已经完整持久化。

发生只读告警时，先另存原件，再检查 JSON、权限或外部写入来源。手工修复后重启桥接
重新加载；独立存储调用方可显式 `load()`。不要用空文件代替损坏文档。

JSONL 日志和纯文本令牌文件沿用各自的追加或原子文本写入协议，不当作 JSON 文档迁移。
